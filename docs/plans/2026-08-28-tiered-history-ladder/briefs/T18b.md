**F1 — the tabbed shell (ADR 0027 decision 1).** Inside the settings dialog, add one `role="tablist"` with five tabs — **General · History · Metrics · Thermals · Advanced** — and move the existing fieldsets into `role="tabpanel"` containers **unchanged in content**: General ← `:412` "This Browser" + `:452` "This Daemon"; History ← `:587`; Thermals ← `:679`; Advanced ← `:651` (F4 adds to it); Metrics is new (F3). **Not a drawer, not an accordion** (Michel has ruled against drawers, and ADR 0027 rejects both). Accessibility is part of the deliverable, not polish: each tab is a `<button role="tab">` with `aria-selected`, `aria-controls`, and **roving `tabindex` — the selected tab is `0`, every other is `-1`**; each panel is `role="tabpanel"` with `aria-labelledby` pointing at its tab; **ArrowLeft/ArrowRight move between tabs (wrapping), Home/End jump to first/last, and moving focus selects**. The selected tab persists in `localStorage` under one key, **every read and write wrapped in `try/catch`** (it throws in private mode and where site data is blocked), defaulting to General.

  **🔴 THE THREE WAYS THIS FINDING SILENTLY BREAKS THE SETTINGS FORM — each needs its own test:**
  1. **Panels must stay in the DOM and be hidden with the `hidden` attribute — NEVER detached, never conditionally rendered.** `settingsFormControls()` (`:647`) and `collectDaemonSettingsFromForm()` (`:2943`) read *every* control by `document.querySelector`. A control inside a removed panel returns `null`, `collectDaemonSettingsFromForm` silently substitutes its fallback, and **the user's saved settings quietly revert to defaults for every tab they did not visit.** Test: with the Metrics tab selected, `collectDaemonSettingsFromForm()` still returns the History-tab and Thermals-tab values unchanged.
  2. **Switching a tab must NOT mark the form dirty.** A tab change is a view change; `state.settingsDirty` must be untouched and the `:696` indicator must not appear. Test: select each of the five tabs in turn, assert `settingsDirty === false` and the indicator stays hidden.
  3. **A remembered tab that is hidden must fall back to General.** Thermals hides without `thermalAvailable` and Metrics hides without the route (F3); restoring `"thermals"` on a host without it would open the dialog onto nothing. Test: `localStorage` holds `"thermals"`, capability absent → General is selected and the Thermals tab is not in the tablist.

**F2 — hidden tabs, not empty tabs (ADR 0027 decision 1).** A tab whose panel has no available content is **removed from the tablist entirely**, never shown-and-empty: **Thermals** follows `state.thermalAvailable` exactly as `:2929 syncRetentionLadderAvailability()` already hides `thermal-settings-group`; **Metrics** follows F3's availability. Fold this into `syncRetentionLadderAvailability()` rather than inventing a second mechanism. On the Bun runtime both are absent and the dialog shows three tabs. Tests: with no capabilities the tablist holds exactly General/History/Advanced; with both, five; and in every case the *selected* tab is one that exists.

**F3 — the Metrics tab, rendered from the route and never hardcoded (ADR 0027 decision 4, UI half).** On opening settings, `GET /api/otel/metrics`. **A non-OK response or a network error hides the Metrics tab** (F2) — it is not an error state, it is an older or Bun daemon. On success, render one checkbox per registry entry **grouped by `family`**, in registry order, each row showing `name`, `unit` and `description`, with a per-family **select-all/none affordance that expands to explicit names at save time** (ADR 0027 rejects storing a wildcard). Entries from `unknown` render in a final read-only block labelled **"unknown on this version (inert)"** — visible, never editable, never silently dropped.

  **🔴 THE TWO INVARIANTS THAT MAKE OR BREAK THIS FINDING:**
  1. **DIRECTION.** The wire stores the **disabled** set; the UI shows **enabled** checkboxes. **A checked box means the name is ABSENT from `otel.disabledMetrics`.** Test: check every box → `disabledMetrics` is `[]`; uncheck exactly `system.cpu.utilization` → `disabledMetrics` is exactly `["system.cpu.utilization"]`.
  2. **UNKNOWN NAMES MUST SURVIVE THE ROUND TRIP.** If you rebuild `disabledMetrics` from the checkboxes alone, every unknown name is **destroyed on the next save** — which is precisely the fleet-portability guarantee ADR 0027 decision 3 exists to provide (Michel runs one configuration across boxes on different releases). **The saved value is `unknown ∪ {registry names whose box is unchecked}`**, and the unknown half is carried through untouched and unreordered. Test, and name it so the next reader cannot miss it: `unknown_disabled_metrics_survive_a_save_untouched` — load a document whose `disabledMetrics` is `["system.future.metric","system.cpu.utilization"]`, re-check `system.cpu.utilization`, save, and assert the payload is exactly `["system.future.metric"]` — not `[]`, not reordered.

**F4 — the Advanced tab: the raw document, validated by the server (ADR 0027 decision 5).** The Advanced panel keeps the existing OTel expert controls (`:651` — endpoint, protocol, headers env var, resource attributes) and gains a raw-document editor: a `<textarea>` seeded from `GET /api/settings/export`, a **Validate** button that posts the text through the existing dry-run (`:3144 previewSettingsImport()`) and renders the outcome with the existing `:2648 renderSettingsValidation()` (its `errors` list, or the `changed_keys` it would apply), and an **Apply** button that is **`disabled` until a validation of the current exact text has succeeded**. **The client never re-implements validation** — it displays the server's verdict, so the two can never disagree (decision 5). **🔴 Apply must return to `disabled` on every `input` event in the textarea**, or a stale success authorises applying a document the server never saw. Tests: Apply starts disabled; a failing validation renders the server's errors and leaves it disabled; a passing one enables it; **editing one character after a pass disables it again**; and malformed JSON is reported as a validation failure, never thrown.
