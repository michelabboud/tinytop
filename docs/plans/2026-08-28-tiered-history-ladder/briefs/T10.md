`plan_import` is **read-only** and returns `Err` only for store failures (sqlx/io); every document problem lands in `errors[]` with `valid: false` (envelope errors included — the dashboard and the CLI print one shape). Steps, in order, stopping at the first group that fails: (a) envelope: the body must be a JSON object; every top-level key must be in `ENVELOPE_KEYS` — otherwise `unknown top-level key "<k>"; allowed keys: tinytopConfigVersion, exportedAtMs, agentVersion, settings` (one error per unknown key, sorted); `tinytopConfigVersion` missing or not an integer → `tinytopConfigVersion is required and must be an integer (maximum supported: 1)`; `> MAX_CONFIG_VERSION` → `tinytopConfigVersion <v> is newer than the maximum supported 1; export from a matching agent or downgrade the document`; `< 1` → `tinytopConfigVersion <v> must be ≥ 1 (maximum supported: 1)`; `settings` missing or not an object → `settings is required and must be an object`; `exportedAtMs`/`agentVersion` are optional on import and informational (never validated; an `agentVersion` that differs from the running agent's is NOT an error). (b) decode: `previous = store.get_settings()`, `disk_pressure = store.history_state_get::<DiskPressureState>("diskPressure").unwrap_or_default()`, `candidate = DashboardSettings::from_document(settings_value.clone(), Some(&previous.retention_ladder))` (decode error → its `Validation` message in `errors[]`), then `candidate.normalize_legacy_mirrors()` (**new 3-line `pub fn` on `DashboardSettings` in `lib.rs`, extracted from `put_settings:743-744`, which now calls it — behaviour byte-identical**). (c) validate: `candidate.validate()` and `candidate.retention_ladder.validate(Some(&disk_pressure), Some(&previous.retention_ladder))` — each `Err` message pushed to `errors[]` (the validators stop at their first failing rule, exactly as PUT does today — do not rewrite them; document that `errors[]` therefore lists at most one message per validator). (d) `warnings[]`: unknown keys INSIDE `settings` are ignored by serde (PUT parity) but listed: walk the input object against `serde_json::to_value(&candidate)` recursively over object members and report each key present in the input but absent from the re-serialised candidate as `settings.<dotted.path>: unknown key ignored`, sorted. (e) `changed_keys = DashboardSettings::changed_keys(&previous, &candidate)` — **`changed_setting_keys` MOVES verbatim from `writer.rs:944-980` into `lib.rs` as `pub fn changed_keys(previous: &Self, next: &Self) -> Vec<&'static str>`** (its test `:1971` moves to `tinytop-store/tests/settings_transfer.rs` unchanged in substance); `update_settings` calls the method — one diff function for PUT, dry-run and import. (f) `would_delete` (only when `valid`; zeros otherwise) per **F2**. `candidate` is `Some` only when valid.

`apply_import` = `plan_import` → if `!valid` → `Err(StoreError::Validation(errors.join("; ")))` and NOTHING written → else `let saved = store.put_settings(&candidate).await?` (the second validation inside `BEGIN IMMEDIATE` is the authoritative one — the plan's read is a preview, so a disk-pressure breach between preview and apply is still refused, with the same message; test it) → `Ok(ImportOutcome { settings: saved, changed_keys, would_delete })`. `apply_import` does NOT record the marker and does NOT run maintenance — the callers do (F3/F4), because the API path must run `maintain_history` between the write and the marker (spec §10) while the CLI must not run maintenance at all (F4).

**F2 — `wouldDelete` is server-computed from the prune predicates, never estimated.** New `pub async fn count_rows_older_than(&self, tier: Tier, cutoff_ms: i64) -> Result<i64, StoreError>` on `SqliteHistoryStore` in `lib.rs`, ONE `SELECT COUNT(*)` per call mirroring the delete it predicts: `Tier::L1` → `FROM metric_samples WHERE captured_at_ms < ?` (= `prune_raw_history`); `L2`/`L3`/`L4` → `FROM {tier.table()} WHERE bucket_start_ms + ? <= ?` binding `tier.resolution_ms()` and `cutoff_ms` (= `prune_rollups`). Plus `pub async fn count_snapshot_json_older_than(&self, cutoff_ms) -> Result<i64, StoreError>` mirroring `strip_snapshot_json`'s predicate (read it; `snapshot_json IS NOT NULL AND captured_at_ms < ?`). Cutoffs come from the CANDIDATE ladder through the SAME conversion `maintenance.rs` uses to build `MaintenanceConfig` (call that builder — make it `pub(crate)` if private — never re-derive `× DAY_MS` in the new module): `l1_rows = count(L1, now − l1_keep_ms)`; `l2_buckets = count(L2, now − l2_keep_ms)`; `l3_buckets = config.l3.map(count) else 0` (a disabled tier prunes nothing — its rows are KEPT, spec §9); `l4_buckets = config.l4.filter(>0).map(count) else 0` (forever = 0; when the candidate's `archive.queryable` is true these rows are moved into the archive, not deleted — the number is still what leaves `main`; the dashboard words it, F5); `snapshot_json_rows = count_snapshot_json_older_than(now − snapshot_json_keep_ms)`. Document the one caveat in the architecture doc: the counts are "older than the candidate horizon" — rows already past the CURRENT horizon but not yet pruned (the L2/L3 prunes are watermark-gated and bounded per tick) are included, and the prune may take several ticks to reach the number; it never deletes more.
