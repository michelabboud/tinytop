| [0018](0018-archive-move-commits-copy-before-delete.md) | Accepted (2026-08-29) | The L4 → archive move is two transactions on one attached connection — commit the copy into `history-archive.sqlite` first, verify it, then delete from main — because SQLite commits attached WAL databases file-by-file in ATTACH order (`main` first), so the spec's single cross-db transaction could lose a batch on a crash; amends 0014 Decision 1 |

| [0020](0020-hourly-disk-check-keeps-last-state-when-undeterminable.md) | Accepted (2026-08-29) | Hourly disk check: an undeterminable measurement keeps the last known state (never fails closed like 0017's one-shot guard, never fails open); no hysteresis; state + `lastDiskCheckMs` + marker commit in one transaction; first check at daemon start on a blocking thread |
| [0021](0021-cadence-classes-and-typed-history.md) | Accepted (2026-08-29) | Cadence classes (fast / slow / static) owned by the collector; history typed, `snapshot_json` dropped; processes fast with a command dictionary; filesystems stored on change; `/api/snapshot` from memory. |
| [0022](0022-gpu-telemetry-kernel-interfaces-detection-gated.md) | Accepted (2026-08-29) | GPU telemetry from kernel/OS interfaces only (Linux DRM sysfs + fdinfo + hwmon; Windows PDH + DXGI; macOS IOKit), detection-gated, never a subprocess or vendor library; extends 0012. |
| [0023](0023-schema-v2-migration-one-transaction-no-pre-image.md) | Accepted (2026-08-29) | Schema v2 (T13) migrates v1→v2 in ONE transaction with an in-flight guard (`command_id IS NULL` count must be 0 → else rollback) and NO pre-image (v1→v2 loses nothing; the v0→v1 pre-image existed for deliberate JSON loss); `sqlite_version()` ≥ 3.35 checked before any write; `command_id` indexed on both process tables (orphan prune is O(log n), gated on deletions); `started_at` stays TEXT until T14; fresh files created directly in v2 shape; extends 0021. |
| [0024](0024-schema-v3-typed-history-identity-interning-filesystems-on-change.md) | Accepted (2026-08-30) | Schema v3 (T14): `metric_samples` rebuilt in ONE transaction without `snapshot_json` (thread columns nullable; per-row uptime, the three scalars and the filesystem stamp; `identity_id` with a CHECK that an assembleable row carries every scalar; rows already stripped stay non-assembleable — nothing borrowed from a neighbour), `host_identity` interning of the eight identity strings, filesystems on change keyed by the enumeration stamp with `fs_mount_events` presence (no time-window heuristic; carry-forward floor kept by the prune), `/api/history` assembled from typed tables, pressure not stored (dashboard renders `—`), `started_at` → v4; extends 0021/0023. |
| [0025](0025-schema-v4-gpu-storage-and-started-at-ms.md) | Accepted (2026-08-30; T15/T15b, 0.5.4) | Schema v4: `started_at` → `started_at_ms INTEGER` by rebuilding BOTH process tables (unparsable text → NULL and counted, never a refusal; RFC 3339 formatted at read), `gpu_adapters` interned with an integer surrogate + `stable_id` (amends the plan's TEXT key; `last_seen_ms` once a minute), `gpu_samples` WITHOUT ROWID pruned at L1 with `wouldDelete.gpuSampleRows`, `gpu_percent` on the minute tier too; Linux busy = Task Manager's rule (per engine Σ client deltas / capacity × Δt, max engine, cap 100; dedup on pdev + client-id; decreases → 0) over pids readable by the daemon's uid (a documented lower bound); `gpu_busy_percent` preferred, its unsupported verdict cached until re-detect; two lanes, one tag; extends 0022/0024. |
| [0026](0026-schema-v5-thermal-sensors-opt-in.md) | Accepted (2026-08-30; T17/T17b) | Schema v5 (T17, thermals): `sensor_dim` + `sensor_samples` (interned integer key, `stable_id` never the unstable `hwmonN` index, thresholds in the dimension, `WITHOUT ROWID` raw tier pruned at L1 with `wouldDelete.sensorSampleRows`) — purely additive, no rebuild; **opt-in `thermal.enabled` default `false`** in the ADR 0015 mould, disabled = hwmon never read; the parent sensors plan's `sensors[]` contract adopted verbatim and narrowed to `kind: "temp"`; CPU chips by allow-list (`coretemp`/`k10temp` + `thermal.extraChips`) so `gpus[].temperatureC` is never double-reported; a threshold outside `0 < t ≤ 200 °C` is absent, never a number; own `section.panel`, hidden when absent; extends 0015/0022/0025. |
| [0027](0027-tabbed-settings-and-otel-metric-selection.md) | Accepted (2026-08-30; T18/T18b) | Settings page becomes TABBED (General · History · Metrics · Thermals · Advanced; ARIA tablist, never a drawer, last tab remembered, absent-support tabs hidden); OTel metric selection stored as the **DISABLED** set (`otel.disabledMetrics`, default empty) so a metric added in a later release ships ON rather than silently off — the shadow-state failure the enabled-list direction would guarantee; an unknown name is accepted, preserved and shown inert (fleet config portability across versions); the 13 metric names become ONE `METRIC_REGISTRY` in the daemon that `Instruments::new` builds from and `GET /api/otel/metrics` serves, so the UI never hardcodes the list and advertised/exported cannot drift; a disabled metric is never recorded, not recorded-then-stripped; Advanced tab carries the raw config document with validate-before-apply reusing `plan_import`'s server-side verdict; two lanes, one tag; extends 0015/0016/0026. |
| [0028](0028-settings-booleans-are-restyled-native-checkboxes.md) | Accepted (2026-09-01; 0.7.0) | Settings-dialog booleans are presented as SWITCHES by restyling the native `input[type="checkbox"]` in place (`appearance: none` + `::after` knob, scoped to `.settings-dialog`, `role="switch"`) rather than a wrapper component, a scripted control or a library — one rule set then covers both the thirteen static fields and the metric picker built at runtime, so the two cannot drift; the on-state pairs `--cyan` with `--surface`, which each theme remaps to its own accent (`ember` = `#fb923c`) and which invert correctly on light `solar`; a switch means an on/off SETTING while a checkbox still means SET MEMBERSHIP, so the history-series and filesystem-filter checkboxes outside the dialog are deliberately left alone; alignment fixed alongside (the `float: right` legend button, the magic `margin-top` on the metric row, and the unit that occupied its own line); extends 0027. |
| [0029](0029-settings-dialog-is-a-fixed-box.md) | Accepted (2026-09-01; 0.7.1) | The settings dialog is ONE FIXED BOX for every tab (`height: min(820px, calc(100dvh - 2rem))`), because a content-sized dialog shrank on a tab switch and — since a dialog is centred and the tab's `focus` handler fires on mousedown — resized BETWEEN mousedown and mouseup, so the mouseup landed on the backdrop and `click` (dispatched to the common ancestor) dismissed the dialog mid-click; a backdrop dismiss now also requires the gesture to have STARTED on the backdrop, which additionally stops a drag-to-select in the document editor from discarding the edit; every tab FITS the box without scrolling (Metrics families side by side 884→621, Advanced split into OTel-left / raw-document-right 783→447, General tightened 672→629 against 650), and selectors that tie with `.settings-group` are panel-scoped because source order silently killed them; extends 0027/0028. |
| [0030](0030-live-samples-never-enter-a-historical-window.md) | Accepted (2026-09-01; 0.7.1) | Only the `live` window charts polled samples: `renderSnapshot` gates `pushHistory` on `liveSampleEntersHistory` and, for a historical window with nothing scrubbed, renders the tiles directly via `liveSampleDrivesTiles` so the chart shows the past while the gauges still report NOW. The unconditional push made a chosen window pile up live points at its right edge and — because the hydrated window arrives at the 1200-sample render cap — `trimHistory` EVICTED its oldest point once per tick, replacing the selected range with live data within ~30 min. Tile render must run AFTER `renderSelectedSample`, which otherwise re-renders tiles from the window's last stored raw sample and freezes the gauges; ordering pinned by test. |
| [0031](0031-a-settings-write-configures-the-collector-immediately.md) | Accepted (2026-09-01; 0.7.x) | A settings write configures the collector immediately: BOTH write paths (`PUT /api/settings` and `POST /api/settings/import`, never the `dryRun` branch) call the configure path once the write has committed, so a toggle no longer reads as a broken switch for up to a tick. The naive nudge — passing the caller's settings value — is REJECTED: the tick reads settings and applies them six lines and one `maintain_history` prune apart, so a write landing in that window is reverted for a tick by the tick's older snapshot, and the `applied == desired` guard cannot see it. Instead `configure_collector_if_changed` loses its settings parameter and reads the row ITSELF while holding `collector_config`, making that mutex the single serialization point: the last writer to the store is always the last writer to the collector. Costs one extra single-row read per tick under a zero-contention lock; holds a `tokio` mutex across an `.await`, which is NOT the OTel status-guard invariant and should not be flagged as one. The tick order is otherwise unchanged, and the idempotence guard becomes load-bearing rather than an optimisation. Amends the T12 tick-ordering rationale. |
| [0032](0032-one-switch-implementation.md) | Accepted (2026-09-01; 0.8.2) | There is exactly ONE switch implementation in the settings dialog. `styles.css` carried two that did not override each other because they drew the knob with DIFFERENT pseudo-elements — ADR 0028's `.settings-dialog input[type="checkbox"]` via `::after` at specificity (0,1,1), and a legacy v0.1.31 `.settings-group .toggle-row input[type="checkbox"]` via `::before` at (0,2,1) which won on track size and colour — so all 13 switches rendered TWO knobs travelling 18px and ~13.8px over one track, reading as a smeared or mid-travel toggle. ADR 0028 caused the very drift it existed to prevent: it added a second rule set and left the first in place (third such failure in this file, after `.metric-family` and `.advanced-document-settings-group`). The legacy block is deleted and ADR 0028's rule survives, because only it reaches the runtime-built metric picker rows; it ADOPTS the legacy geometry (42×24 track, 16px knob, 18px travel) since that is what the user has seen since v0.1.31 and 24px is the better pointer target, while KEEPING ADR 0028's `--cyan`/`--surface` pair so each theme remaps the accent instead of pinning literal `--amber`. Amends 0028's geometry; 0028's restyle-in-place decision stands. Acceptance is a rendered check of every switch in both themes — no unit test can see two knobs. |
