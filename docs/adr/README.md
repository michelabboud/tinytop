# Architecture Decision Records

This directory tracks architectural decisions that are expensive to reverse or likely to raise "why" questions for future contributors.

| ADR | Status | Decision |
| --- | --- | --- |
| [0001](0001-sqlite-writer-process.md) | Superseded by [0005](0005-rust-single-daemon-systemd-runtime.md) | Use a dedicated Bun writer process as the only SQLite owner in the original Bun split runtime. |
| [0002](0002-initial-snapshot-json-history.md) | Accepted | Store initial history as indexed metric columns plus full snapshot JSON. |
| [0003](0003-bash-bootstrap-bun-install-wizard.md) | Accepted | Use a Bash bootstrap command center that launches a Bun setup wizard after Bun is available. |
| [0004](0004-rust-agent-sqlx-store.md) | Accepted | Add an additive Rust collector/agent path and use SQLx for Rust-side storage. |
| [0005](0005-rust-single-daemon-systemd-runtime.md) | Accepted | Use a single Rust daemon as the default systemd runtime while keeping the Bun split path as fallback. |
| [0006](0006-embedded-dashboard-assets.md) | Accepted | Embed dashboard assets in the Rust collector while keeping the legacy Bun dashboard asset tree. |
| [0007](0007-daemon-and-browser-dashboard-settings.md) | Accepted; presentation refined by [0008](0008-settings-dialog-presentation.md) | Split dashboard settings between browser-local preferences and SQLite-backed daemon defaults. |
| [0008](0008-settings-dialog-presentation.md) | Accepted | Present dashboard settings as a dialog instead of an inline dashboard section. |
| [0009](0009-additive-history-points-and-markers-api.md) | Accepted | Keep raw history backward compatible and add chart-point plus timeline-marker APIs for rollup-backed ranges. |
| [0010](0010-feature-gated-native-platform-collectors.md) | Accepted | Keep Linux as the default collector while adding opt-in macOS and Windows native collector modules. |
| [0011](0011-powershell-first-windows-command-center.md) | Accepted | Add a PowerShell-first Windows command center before Scoop, winget, or MSI packaging. |
| [0012](0012-rust-inode-collection-via-statvfs.md) | Accepted | Collect Rust inode data via `statvfs(2)` (rustix) instead of a `df -i` subprocess, preserving the no-shell-out invariant. |
| [0013](0013-tiered-history-ladder.md) | Proposed (2026-08-28, at Michel's gate) | Four-tier history ladder (raw → 1 min → 5 min → 1 h) with fold-not-decimate, frozen completed buckets, promote-before-prune, a recent-window-only `snapshot_json`, typed detail tables, and a pre-imaged v0→v1 migration; supersedes 0009's "no multiple rollup tables" |
| [0014](0014-archive-tiers-queryable-sqlite-and-cold-csv-gzip.md) | Proposed (2026-08-28) | Two archive tiers: expired hourly rows move into a queryable `history-archive.sqlite`; months older than a threshold export as verified `tinytop-1h-YYYY-MM.csv.gz` + `.sha256` (CSV measured smaller than compressed SQLite) |
| [0015](0015-opentelemetry-metrics-push-export.md) | Accepted (2026-08-29; T11, 0.5.0) | Push-only OTLP metrics export over HTTP/protobuf, off by default, semantic-convention names, headers from an env var — no read path |
| [0016](0016-configuration-export-import-document.md) | Accepted (2026-08-28; T10, 0.4.1) | Versioned, secret-free settings document with export, dry-run import, and server-computed deletion counts |
| [0017](0017-store-owns-its-free-space-check.md) | Accepted (2026-08-28) | `tinytop-store` owns its free-space check on `sysinfo` (already pinned) — never a dependency on `tinytop-collectors`, never a unix-only `statvfs` |
| [0018](0018-archive-move-commits-copy-before-delete.md) | Accepted (2026-08-29) | The L4 → archive move is two transactions on one attached connection — commit the copy into `history-archive.sqlite` first, verify it, then delete from main — because SQLite commits attached WAL databases file-by-file in ATTACH order (`main` first), so the spec's single cross-db transaction could lose a batch on a crash; amends 0014 Decision 1 |
| [0019](0019-archive-move-keyset-verify-fullrow-delete-fsynced-copy.md) | Accepted (2026-08-29) | Archive move, after the T7 blind review: verify by key-set existence (an interval count livelocks after a partial batch), delete by full-row equality, `PRAGMA archive.synchronous = FULL` so the copy is fsynced before the main delete (main stays NORMAL), watermark inside the delete transaction, schema DDL in one transaction; supersedes 0018 steps 3–5 and records its errata (lock pins libsqlite3-sys 0.37.0 = SQLite 3.51.3; `synchronous` is NORMAL) |
| [0020](0020-hourly-disk-check-keeps-last-state-when-undeterminable.md) | Accepted (2026-08-29) | Hourly disk check: an undeterminable measurement keeps the last known state (never fails closed like 0017's one-shot guard, never fails open); no hysteresis; state + `lastDiskCheckMs` + marker commit in one transaction; first check at daemon start on a blocking thread |
| [0021](0021-cadence-classes-and-typed-history.md) | Accepted (2026-08-29) | Cadence classes (fast / slow / static) owned by the collector; history typed, `snapshot_json` dropped; processes fast with a command dictionary; filesystems stored on change; `/api/snapshot` from memory. |
| [0022](0022-gpu-telemetry-kernel-interfaces-detection-gated.md) | Accepted (2026-08-29) | GPU telemetry from kernel/OS interfaces only (Linux DRM sysfs + fdinfo + hwmon; Windows PDH + DXGI; macOS IOKit), detection-gated, never a subprocess or vendor library; extends 0012. |
| [0023](0023-schema-v2-migration-one-transaction-no-pre-image.md) | Accepted (2026-08-29) | Schema v2 (T13) migrates v1→v2 in ONE transaction with an in-flight guard (`command_id IS NULL` count must be 0 → else rollback) and NO pre-image (v1→v2 loses nothing; the v0→v1 pre-image existed for deliberate JSON loss); `sqlite_version()` ≥ 3.35 checked before any write; `command_id` indexed on both process tables (orphan prune is O(log n), gated on deletions); `started_at` stays TEXT until T14; fresh files created directly in v2 shape; extends 0021. |
| [0024](0024-schema-v3-typed-history-identity-interning-filesystems-on-change.md) | Accepted (2026-08-30) | Schema v3 (T14): `metric_samples` rebuilt in ONE transaction without `snapshot_json` (thread columns nullable; per-row uptime, the three scalars and the filesystem stamp; `identity_id` with a CHECK that an assembleable row carries every scalar; rows already stripped stay non-assembleable — nothing borrowed from a neighbour), `host_identity` interning of the eight identity strings, filesystems on change keyed by the enumeration stamp with `fs_mount_events` presence (no time-window heuristic; carry-forward floor kept by the prune), `/api/history` assembled from typed tables, pressure not stored (dashboard renders `—`), `started_at` → v4; extends 0021/0023. |
| [0025](0025-schema-v4-gpu-storage-and-started-at-ms.md) | Accepted (2026-08-30; T15/T15b, 0.5.4) | Schema v4: `started_at` → `started_at_ms INTEGER` by rebuilding BOTH process tables (unparsable text → NULL and counted, never a refusal; RFC 3339 formatted at read), `gpu_adapters` interned with an integer surrogate + `stable_id` (amends the plan's TEXT key; `last_seen_ms` once a minute), `gpu_samples` WITHOUT ROWID pruned at L1 with `wouldDelete.gpuSampleRows`, `gpu_percent` on the minute tier too; Linux busy = Task Manager's rule (per engine Σ client deltas / capacity × Δt, max engine, cap 100; dedup on pdev + client-id; decreases → 0) over pids readable by the daemon's uid (a documented lower bound); `gpu_busy_percent` preferred, its unsupported verdict cached until re-detect; two lanes, one tag; extends 0022/0024. |
| [0026](0026-schema-v5-thermal-sensors-opt-in.md) | Accepted (2026-08-30; T17/T17b) | Schema v5 (T17, thermals): `sensor_dim` + `sensor_samples` (interned integer key, `stable_id` never the unstable `hwmonN` index, thresholds in the dimension, `WITHOUT ROWID` raw tier pruned at L1 with `wouldDelete.sensorSampleRows`) — purely additive, no rebuild; **opt-in `thermal.enabled` default `false`** in the ADR 0015 mould, disabled = hwmon never read; the parent sensors plan's `sensors[]` contract adopted verbatim and narrowed to `kind: "temp"`; CPU chips by allow-list (`coretemp`/`k10temp` + `thermal.extraChips`) so `gpus[].temperatureC` is never double-reported; a threshold outside `0 < t ≤ 200 °C` is absent, never a number; own `section.panel`, hidden when absent; extends 0015/0022/0025. |
