    This Browser

    Applies to this browser only and is remembered locally. These override the daemon defaults without changing what anyone else sees.

    Daemon defaults

    What a browser sees before it has preferences of its own, and how hard the daemon works. A shorter refresh gives a livelier chart at the cost of CPU and database writes; the budget is the size history is pruned back to.

    Alert thresholds

    The percentages that turn a panel amber, then red. A preset fills all ten at once; editing any single value switches the preset to Custom. Lower numbers warn earlier and more often.

    Sections & privacy

    Which sections the dashboard offers, and whether process command lines are redacted before they leave the daemon. Hiding a section does not stop it being collected — it only stops it being shown.

    History ladder — Rust daemon only

    Retention tiers

    How long each resolution of history survives. L1 keeps every sample, L2 one point a minute, L3 one per five minutes, L4 one per hour. The coarse tiers are what make years of history affordable — raising L1 costs the most disk per day by a wide margin.

    Archive

    What happens to samples older than the ladder. Queryable keeps them readable in a side database; cold writes .csv.gz files you can move off the machine, and stops answering queries from them. Leave the directory blank to use the main database directory.

    Disk guard

    How often the daemon samples filesystem detail and checks its own footprint. Below the minimum free space it stops writing history rather than filling the disk — so this is the setting that decides whether TinyTop can ever be the reason a machine runs out of room.

    These switches decide which metrics leave the daemon over OpenTelemetry. Unchecking one does not stop it being collected and does not change anything on this dashboard — it only removes it from the export.
